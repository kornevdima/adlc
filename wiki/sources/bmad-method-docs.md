# BMAD Method documentation

The docs home is thin. The planning pages (choose a planning path, define requirements and a specification, design UX and architecture, break work into stories and track it) are listed in navigation but were not read.

## What the home page settles

- The loop has four moves: Clarify, Plan, Build and verify, Learn and adjust. Learn and adjust returns to planning.
- Work enters at the point that matches how formed it is, so a small change skips planning.
- The method ships as skills, not fixed personas. The page names one agent, a Product Owner, and a build skill that writes the code and reviews it in one pass.

## What it does not settle

The home page does not list the planning documents, the role-to-document mapping or the sprint status file. A web search returned community guides and a Mintlify mirror. They agree on the chain analyst brief, product manager PRD and epics, architect design, then a sprint-status file that tracks story states. One guide conflicts with the others on whether the scrum master and QA agents still exist: it says the current official repository consolidated both into the developer agent, while older guides and forks still show them. The official home page's single build skill that also reviews supports the consolidated reading but does not prove it.
