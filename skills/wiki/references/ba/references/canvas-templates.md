# Canvas Templates

## Purpose
Use this reference during Step 5 (Prepare Canvas) of ba-workshop-facilitator.
Each canvas is reproduced in structured table form. Include the relevant canvas(es) in the
Word facilitator guide and PowerPoint deck as formatted tables, one cell per quadrant or section.

---

## Canvas 1 — Empathy Map

Used with: Framework 1 (Discovery)

```
┌─────────────────────────────┬─────────────────────────────┐
│           SAYS              │           THINKS             │
│                             │                              │
│  (Quotes, statements,       │  (Beliefs, worries,          │
│   words they use)           │   private thoughts)          │
│                             │                              │
├─────────────────────────────┼─────────────────────────────┤
│           DOES              │           FEELS              │
│                             │                              │
│  (Observable behaviours,    │  (Emotions, attitude,        │
│   actions, habits)          │   frustrations, joy)         │
│                             │                              │
└─────────────────────────────┴─────────────────────────────┘
                    ┌──────────────────┐
                    │  PAINS │  GAINS  │
                    └──────────────────┘
```

**In Word/PowerPoint:** Reproduce as a 2×2 table with a 2-cell row below.
Each cell header: bold, sentence case. Body: empty for workshop use (participants fill in).

## Canvas 2 — Impact Map

Used with: Framework 2 (Discovery / Requirements)

Hierarchical tree structure. Reproduce as a nested list or table.

```
GOAL (measurable, time-bound)
│
├── ACTOR 1 (who can influence the goal?)
│   ├── IMPACT: How should Actor 1's behaviour change?
│   │   └── DELIVERABLE: What can we build to drive that change?
│   └── IMPACT: (another impact for Actor 1)
│       └── DELIVERABLE:
│
├── ACTOR 2
│   └── IMPACT:
│       └── DELIVERABLE:
│
└── ACTOR 3
    └── IMPACT:
        └── DELIVERABLE:
```

**In Word:** Reproduce as an indented table (4 columns: Goal | Actor | Impact | Deliverable).
**In PowerPoint:** Use a SmartArt-style hierarchy or a simple four-column table.

| Goal | Actor | Impact | Deliverable |
|------|-------|--------|-------------|
| [State goal here] | | | |
| | Actor 1 | | |
| | | Impact 1a | |
| | | | Deliverable 1a |

## Canvas 3 — Event Storming Board

Used with: Framework 3 (Discovery / Process Mapping)

Colour-coded sticky note legend. Reproduce as a legend table in the facilitator guide.

| Sticky Note Colour | What It Represents | Examples |
|-------------------|-------------------|----------|
| Orange | Domain Event (something that happened, past tense) | "Order placed", "Payment confirmed", "Account created" |
| Blue | Command (instruction that triggered the event) | "Place order", "Confirm payment" |
| Yellow | Actor (person who issued the command) | "Customer", "Finance team", "Automated job" |
| Pink | System / External System | "Payment gateway", "ERP", "Email service" |
| Red | Hotspot / Problem / Question | "Why does this fail?", "Who owns this?" |
| Green | Read Model / View (what data is needed to make a decision) | "Dashboard showing pending approvals" |
| Lilac | Policy / Business Rule (when X, then Y) | "If order > £1000, require manager approval" |

**Timeline instruction for participants:**
Place your orange events in rough chronological order, left to right.
Do not discuss yet. Just place. Duplicates are fine — we will sort them later.

## Canvas 5 — Swimlane Process Map

Used with: Framework 5 (Process Mapping)

Vertical swimlanes, one per actor or system. Reproduce as a table with role headers.

| [Role / Actor 1] | [Role / Actor 2] | [System 1] | [System 2] |
|-----------------|-----------------|------------|------------|
| Step 1: [action] | | | |
| ↓ | | | |
| Decision: [condition] | | | |
| ↓ Yes | ↓ No | | |
| Step 2a | Step 2b | | |

**Facilitator note:** In the workshop, draw this live as participants narrate.
Do not pre-fill steps — the act of narrating and capturing in real time is the exercise.

**Pain point annotation:** Add a column at the right edge:

| Pain Points |
|-------------|
| (What hurts at this step? Use sticky notes or comments.) |

## Canvas 6 — How Might We Board

Used with: Framework 6 (Design Sprint)

| Challenge Statement | How Might We Question | Ideas Generated | Votes |
|--------------------|----------------------|-----------------|-------|
| [Pain point or problem] | HMW [reframed as opportunity] | (list ideas) | (dot count) |

**Instruction card for participants:**
1. Read the challenge statement.
2. Rewrite it as "How Might We..." — start with the opportunity, not the problem.
3. Generate as many solution ideas as you can in 10 minutes. One idea per sticky note.
4. Do not evaluate yet.
